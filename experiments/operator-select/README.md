# 同样 600 道题，强化学习前后相差多少？

**训练前 273/600（45.5%），训练后 521/600（86.8%）。** 这是事先指定的主实验。题目给出 `(a ? b) + c = 目标值`，模型在 `+、−、×` 中选一个。训练时只告诉它抽到的符号算得对不对；测试时不提供反馈，两次都选概率最高的符号。

**上课用：** 下载 [单文件演示 classroom.html](classroom.html)，双击即可使用，不需要联网、显卡或安装依赖。也可以用 Excel 打开 [600 题逐题对照 CSV](test-pairs.csv)。运行 WebUI 时，第 3 课有「训练前后同卷」入口。

## 同卷对照

底模均为 Qwen2.5-0.5B-Instruct。训练、验证、测试的数字组合不重叠。三个种子都在固定第 240 步结束；用的是同一张试卷，不能合并为 1800 道独立题。

| 训练种子 | 训练前 | 训练后 | 提升（百分点） | 错转对 / 对转错 | 提升的配对 95% 区间（百分点） |
|---|---:|---:|---:|---:|---:|
| **2026（主实验）** | 273/600 | **521/600（86.8%）** | **+41.3** | 248 / 0 | +37.5 至 +45.3 |
| 2027 | 273/600 | 500/600（83.3%） | +37.8 | 285 / 58 | +32.7 至 +43.0 |
| 2028 | 273/600 | 373/600（62.2%） | +16.7 | 274 / 174 | +9.8 至 +23.5 |

主实验双侧精确 McNemar 检验 p = 4.42 × 10⁻⁷⁵；区间是按测试题配对重采样的结果，**不包含**重训造成的波动。最弱的一次也进步了，但改对 274 题的同时退步了 174 题。只看平均分会错过这种差异。

## 三分钟怎么讲

1. **先让学生选：** `(18 ? 14) + 4 = 8`。训练前模型选 `+` 得到 36，三次训练后都选了 `−` 得到 8。每次抽样都能拿到明确的 0 或 1，模型不用先学会输出标签和完整算式才能收到反馈。
2. **再拆总分：** 每种符号各有 200 道测试题。冻结模型的加、减、乘分别做对了 **199、31、43** 题；主实验训练后是 **200、160、161**。进步主要来自原来较弱的减法和乘法选择。
3. **最后问它真的会算了吗？** 一个完全不看 `a,b,c` 的规则，仅根据训练集拟合出「目标 ≤ 29 选减；30–69 选加；更大选乘」，就在同一测试集做对了 **487/600（81.2%）**。所以这个实验有力说明 *RL 能改善这个任务上的决策*，不说明模型学会了通用算术；要区分心算和猜大小，需要另一份专门控制目标大小的试卷。

原始[自由生成 Countdown 实验](../countdown-replay.md)仍保留。它和这组实验的动作空间、训练量及评估设置不同，不能拿两组分数之差当成 RL 的效果。

## 复核与复跑

[训练前锁定的方案](protocol.md) · [主种子逐题原始记录](seed-2026.json) · [重复实验 A](seed-2027.json) · [重复实验 B](seed-2028.json)。三组从同一底模快照 `7ae557604adf67be50417f59c2c2f167def9a775` 分别初始化；RTX 4070 Ti，BF16，LoRA r=16，PyTorch 2.7.1+cu126 / Transformers 4.57.3 / PEFT 0.17.1。只用验证集画训练曲线，测试集只比较固定末步和关闭适配器的原底模。

在仓库根目录运行 `python3 backend/scripts/verify_operator_pairs.py` 可从三个原始文件重新计算配对统计，无需 GPU。完整复跑需安装 GPU 依赖，并将 `MODEL` 指向同一模型快照：

```bash
for s in 2026 2027 2028; do
  python backend/scripts/record_operator_study.py --model-path "$MODEL" --seed "$s" || exit 1
done
python3 backend/scripts/bundle_operator_study.py
```
